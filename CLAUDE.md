# Gameworld

[readme.md](readme.md) defines every concept of the domain model in a few lines and is the source of every name. Read it first. The detail of a concept is in one of the two generation docs: the map or the society.

## Docs

- [docs/map-generation.md](docs/map-generation.md): the generation rules of the map (geography, climate, biomes, flora and fauna, resources, Prospects, travel network). Read the section for the layer at hand; each section states its region generation stage. Sections 1 and 3-8 hold the structure. Appendices B-D are crop and resource data tables, F is the bedrock types and G the resource groups and catalogue. Section 19 and Appendix E are only pointers: the races moved to society-generation.md.
- [docs/society-generation.md](docs/society-generation.md): the generation rules of the society (races, potential population, factions, cities and towns, families, persons, vocations, looks). Only sections 2, 3, 4, 5.1, 5.2, 5.3, 8.1 and 9.1 are specified and implemented: the races, the races of a region with their potential population, the factions of a region (a ruling faction, sometimes an opposition and lesser factions), the name of a region (section 4.10), the races of a city or a town, the cities and towns of a region with their persons (a count per race, no individual persons yet; a city or a town on every Prospect on show, the capital always a city, and the two shares `Settlement.CityShare` and `Settlement.TownShare`), the name of a city or a town (section 5.3: a first part and a place word, drawn in the Planned stage for every Prospect), the colour list (a faction has a main and a secondary colour, section 4.9) and the tool list (section 8.1: the tools of each vocation, with an emblem weight for the coats of arms to come). The vocations of section 8 and their tools are lists in the Parameter Set and are not drawn yet. The rest of sections 5-9 holds what is decided and what is open. [docs/plans/region-factions.md](docs/plans/region-factions.md) holds the test behind the faction rule and what was weighed, and [docs/research/faction-generation.md](docs/research/faction-generation.md) its sources. [docs/plans/cities-and-towns.md](docs/plans/cities-and-towns.md) holds the measurement behind the cities and towns and what was weighed. Appendix A is the default race list: 28 races, with no plain human race and no sub-races. [docs/races-basis.md](docs/races-basis.md) describes each of them (looks, history, way of life, vocations, factions) and holds the measured shares. Appendix B lists the other society docs.
- [docs/default-parameter-set.json](docs/default-parameter-set.json): the default Parameter Set, grouped by region generation stage. map-generation.md and society-generation.md quote the same defaults in their text; change them together.
- Descriptions and lore: every race, vocation, variant of a vocation, tool, kind of flora and fauna, resource, variant of a resource and biome has a `Description` and a `Lore` in the Parameter Set. They are the texts a picture is to be drawn from (image generation with diffusion models), so an invented thing needs them to look the same every time; no generation rule reads them. A text that is not written is `**missing description**` (`DefaultTexts.Missing`): no text of the defaults is missing (a test checks it). The default texts are in `src/Gameworld.Domain/DefaultTexts.*.cs`, one file per list, built from the basis doc the header of the file names (races-basis.md "Appearance" and "History and lore", tools-basis.md, research/vocations.md section 3, research/flora-and-fauna.md sections 4 and 5) with the citations and research remarks taken out; change a text there, in the basis doc and in default-parameter-set.json together. The resources and their variants are in `src/Gameworld.Domain/Resources.Defaults.cs` (map-generation.md section 14): every resource and every variant has a description and a lore, written in that file with no basis doc behind them; the five arcane variants that are a kind of flora take the texts of that kind. The giant mushrooms are not in the flora note either: their texts are written in `DefaultTexts.Flora.cs`. The biomes are in `src/Gameworld.Domain/Biomes.Defaults.cs` (map-generation.md section 13): the description is the real land the biome stands for, that of the Volcano and the lore of every biome are written in the file. The 476 variants of the vocations are in `DefaultTexts.VocationVariants.cs`, keyed by "vocation id/variant name": each has a description (the work and what a picture of the person shows) and a lore (its standing and customs), written in that file with no basis doc behind them. A bedrock type has the two texts on its entry in `Bedrocks` (the description is what Appendix F says it lies under and gives; the lore is written in `ParameterSet.cs`). The elevation types, the types and the forms of faction, the kinds of settlement and the settlement tiers are enums, so their texts are five lists of `KindTextParameters<T>` in the Parameter Set (`ElevationTypes`, `FactionTypes`, `FactionForms`, `SettlementKinds`, `SettlementTiers`), with the defaults in `src/Gameworld.Domain/KindTexts.cs`: the types and the forms of faction have one line each from society-generation.md sections 4.1 and 4.2, the other descriptions and every lore are written in the file. Export the json with `dotnet run --project src/Gameworld.MapGenerator -c Release -- --export-parameters docs/default-parameter-set.json`.
- [docs/parameter-set.schema.json](docs/parameter-set.schema.json): generated, do not edit. It is the JSON Schema of a Parameter Set file: the description, default and range of every parameter. The descriptions live in `[Description]` attributes in `src/Gameworld.Domain/ParameterSet.cs`; give every new parameter one, then regenerate with `dotnet run --project src/Gameworld.MapGenerator -c Release -- --export-schema docs/parameter-set.schema.json`.
- [docs/map-generation-research.md](docs/map-generation-research.md): why a rule is as it is, what was weighed against it and what is still open. Read it when a rule is questioned or changed.
- [docs/adding-a-race.md](docs/adding-a-race.md): the steps to add a race, to one world through a Parameter Set file or to the default list, and every place that must change with the default list.
- [docs/tools-basis.md](docs/tools-basis.md): 146 real tools for the 51 default vocations, each with a sourced description, invented lore and the fitting vocations. The default `Tools` list of the Parameter Set (`src/Gameworld.Domain/Tools.Defaults.cs`) is built from its names, order and fitting vocations, so change them together. The descriptions (without the sources) and the lore are the default `Description` and `Lore` of the tools. 30 entries are marked partially verified.
- [docs/city-and-town-names.md](docs/city-and-town-names.md): 50 invented city and town names for each of the 28 default races, with a note per race on what its names are built from (drawn from races-basis.md). Material only: no generation rule reads the file. The word lists of the city and town name generator are built from its notes, not from its names. No name repeats, within a race or across races.
- The city and town name generator: society-generation.md section 5.3 is its rule, and [docs/research/city-and-town-naming.md](docs/research/city-and-town-naming.md) the research behind it (section 5.3 lists what differs from the rule the note proposes). The code is in `src/Gameworld.Generation/Names`: `SettlementNameGenerator` (how a name is drawn and joined), `SettlementNameLexicons` (the first parts and the place words of each default race, keyed by race id) and `SettlementNameRules` (what a Prospect gives it). Adding, removing or reordering a word of a lexicon changes the names of every world; a test holds reference names. A race without a lexicon takes the one of its `NameStyle`.
- [docs/NameGenerator-Reuse.md](docs/NameGenerator-Reuse.md): the person-name generator, a port from an earlier project (IdleGame; the doc's links into that repo do not resolve here). The code is `src/Gameworld.Generation/Names`. A race picks one of its three styles with `NameStyle` in the Parameter Set (society-generation.md section 2, the default assignment in Appendix A). Its nine models are the files of `pregenerated-data/`, embedded in the Generation assembly; never re-sort or regenerate them, the names of a seed depend on their exact content.
- [docs/RegionNameGenerator-Reuse.md](docs/RegionNameGenerator-Reuse.md): the region-name generator of the same earlier project: the original, its defects and its Corrected mode. The port is `RegionNameGenerator` (word lists and rules) and `RegionNameRules` (what a region gives it) in `src/Gameworld.Generation/Names`, and its rule is society-generation.md section 4.10, which lists what differs from the doc. Adding, removing or reordering a word of the lists changes the names of every world; a test holds the reference names of the doc.
- [docs/plans/](docs/plans/): one plan per change, each with its status at the top. region-factions, race-caps and cities-and-towns are implemented and keep the measurements behind their rules. prospect-border-clearance (keep Prospects clear of patch borders) is planned, not implemented.
- [docs/races-and-worldbuilding.md](docs/races-and-worldbuilding.md): a framework for building a near-human race. [braindump.md](braindump.md): the user's notes in progress, nothing in it is decided.
- [docs/research/](docs/research/): 22 source notes, about 1.8 MB in all. Ten map notes (2026-11-07 to 11-12) are compiled in the research doc. Nine society notes (2026-11-14 to 11-20) are read directly by society-generation.md, the plans and the basis docs: races, human races, factions, faction generation, vocations, portrait components, heraldry, flora and fauna, and city and town naming. Three notes on comics craft do not feed the generator. Read a note only when the user asks for it, or when a doc cites a section whose detail you need. The ten map notes use the names of an earlier prototype: elevation zone = Zone, zone type = elevation type, lattice = grid, location = Prospect.

## Authority

The readme decides the domain model and the names. map-generation.md decides the generation rules of the map, and society-generation.md those of the society. When two of them disagree, report it to the user before changing either.

The readme also holds the Status of the generation, the Documentation table and how to run the apps (the options of the map generation app, what the demo shows). Update those parts with the change that makes them stale.

## Code

.NET 11, one solution: `Gameworld.slnx`.

- `src/Gameworld.Domain`: the domain model of the readme. No generation logic. `ParameterSet.Default` must equal docs/default-parameter-set.json (a test checks it).
- `src/Gameworld.Generation`: the algorithms of map-generation.md and society-generation.md, one folder per layer. `World` is the entry point: it holds one foundation and computes and caches every layer on demand.
- `src/Gameworld.MapGenerator`: the map generation app (console). `dotnet run --project src/Gameworld.MapGenerator -c Release -- --help`. It writes maps and regions to `out/`.
- `src/Gameworld.Demo`: the demo app (web map viewer). `dotnet run --project src/Gameworld.Demo -c Release`, then open http://localhost:5062. The server is `Program.cs` (the API), `Inspection.cs` ("Under the pointer"), `ViewStatistics.cs` ("Statistics"), `PlaceLabels.cs` (the names of cities and towns) and `Summaries.cs`; the page is `wwwroot/index.html`.
- `tests/Gameworld.Tests`: `dotnet test -c Release`.

Generation code must stay a pure function of the foundation: every random choice goes through `Hashing` with the purpose number the doc gives, and no step may depend on the order regions are generated in (a test checks that too).
